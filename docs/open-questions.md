## ボットに付けるロール

ボットは、付けてもらったロールの範囲を読む。どちらのロールにするかは、サーバーの管理者と決める。

| 案 | 見える範囲 | 書き込み |
|---|---|---|
| (a) 本人と同じロール | 本人と一致する | Discord 側では書ける。「書かない」は、コードとテストで守る |
| (b) 読み取り専用のロール（View Channels と Read Message History だけ） | そのロールに見せたチャンネルだけ。限られた人だけのチャンネルのメンションは、拾えなくなることがある | Discord 側でも書けない |

どちらでも、ボットのロールが本人より広くなっていないかを確かめる検査は、まだ無い。
ボットは本人とは別のメンバーなので、本人のロールが外れても、ボットのロールは残る。

## 溜まったファイルの掃除

`processed/` `drafts/` `failed/` `runs/` に、メッセージの本文が溜まり続ける。保持する日数と、消す仕組み（いまは無い）を決める。

Claude のセッション記録は、Claude Code の既定（30 日で自動削除）に任せている（[ADR-0008](adr/0008-keep-session-transcripts.md)）。

## 実機でまだ確かめていないこと

- 自分が持つロール宛てのメンションを拾えること（確かめた期間に、該当の投稿が無かった）。
- ボットが見えないチャンネルの投稿が、検索に出ないこと。
- 数日分での、取りこぼしの有無。
- 実行記録の `denials`（拒否された操作）が 0 になること。読もうとして拒否されたものがあれば、許可ルールを直す。
- デスクトップ版に同梱の `claude.exe` を使い続けてよいか（アプリの更新で場所が変わる）。安定させるなら、公式 CLI を別に入れて `claude_bin` で指す。
- Claude Code の更新後も、`--bare` なしで、サブスクの認証が通るか（公式は、将来 `-p` の既定を `--bare` にするとしている）。

## PR の無人レビューを有効にする

いまは無効（「依頼あり」と表示するだけ。[ADR-0004](adr/0004-unattended-triage-without-pr-review.md)、[ADR-0013](adr/0013-no-pr-review-path-until-enabled.md)）。
有効にするには、レビューに使う git / gh の操作に限った許可ルールを、実行記録（`denials`）を見ながら育てる。
論点は、レビュー用の worktree の作成・push・フォローアップ PR を、無人でどこまで許すか。別のプロセスで動かせば、レビュー中の 1 時間が、仕分けを止めない。

## 精度の計測

返信ドラフトの採用率と、見落とし（対応不要にしたが、実は要対応だった）の件数を数えて、判断基準（`pipeline/prompts/triage.md`）を直す根拠にする。
迷ったら返信ドラフトの側に倒す方針は、判断基準に入っている。
