# ADR-0019: 鍵と ID を集める所も、スキルが、相手の Chrome で一緒に進める。README のセットアップの図は外す

## 背景と課題

- セットアップは、スキルにした（[ADR-0017](0017-setup-as-a-skill.md)）。ただ、いちばん手間のかかる所（ボットを作る、専用チャンネルと Webhook を作る、ID を写す）は、
  「相手が自分でする」としていて、説明は wiki の 1 ページ（195 行）に書いていた。
- umezy さんから、2026-10-10 に、次の 2 つの指摘があった。「（wiki のページが）長い。鍵を集める所も、Claude in Chrome を含めて、できる限りスキルにしたい」
  「（README のセットアップの図は）冗長。いらない」。
- 各自がボットを作る、と決まった（[ADR-0018](0018-per-person-bot-no-shared-host.md)）ので、この手間は、使う人の数だけ発生する。

## 決定

- **スキルに、鍵と ID を集める手順書（`references/collect-keys.md`）を足す。** Claude in Chrome が使えるときは、相手の Chrome で画面を開いて進める。
  使えないときは、同じ順で、言葉で案内する。
- **相手自身の持ち物は、確かめてから、代わりに作る。** 自分のボット、自分だけのサーバー、その中のチャンネルと Webhook。作る前に、作るものを全部言って「はい」をもらう。
  ADR-0017 の「専用チャンネルづくりも、相手が自分でする」は、ここで変える。
- **鍵が出るボタンは、相手が押す。**（「トークンをリセット」「ウェブフックURLをコピー」、`claude setup-token`）その間、Claude は画面を見ない。
  終わったら、先に別のページへ移動してから、画面を見る。クリップボードは、読まない。鍵は、相手の画面と、メモ帳の中だけを通る。
- **ほかの人がいるサーバーには、何もしない。** メッセージを送らない、設定を変えない。管理者への依頼は、文を用意して、相手が送る。
  ログイン、認証コード、規約への同意、画像認証、ボットを入れる「認証」も、相手がする。
- **ID は、読めるものだけ、画面から読む。** チャンネルの ID はアドレスから、アプリ ID は「一般情報」から。ユーザー ID は、相手に写して、会話に貼ってもらう（鍵ではない）。
- **wiki の「鍵と ID の集め方」は、自分の手で進める人向けの早見に、短くする。**
- **README のセットアップの図を外す。** すぐ下の 3 行と、同じことを言っていた。README の図は、「課題とソリューション」の 1 枚だけにする
  （[ADR-0016](0016-short-readme-details-in-wiki.md) の「図は、それぞれ 1 枚」を、ここで変える）。

### 結果

- 得るもの: 相手に残るのは、「はい」と答える、鍵が出るボタンを押してメモ帳に貼る、管理者に頼む、の 3 つ。wiki のページは、195 行から 90 行ほどになる。
- 引き受けるもの: Discord の画面が変わると、手順書の言葉が古くなる。手順書は、言葉を目印に、毎回、画面を見て確かめるよう書いてある。
- 守ること: スキルに、鍵を会話で受け取る手順、鍵が出ている画面を Claude が見る手順、メッセージを送る手順、ほかの人がいるサーバーを変える手順を、足さない。
- **まだ確かめていないこと:** 作る操作そのもの（アプリ、サーバー、チャンネル、Webhook の作成）を、スキルで通すこと。画面は、最後のボタンの手前まで開いて確かめた
  （2026-10-10）。次に、新しい人のセットアップで通して、直す。

## 採らなかった案

- Claude が「トークンをリセット」も押して、トークンをファイルに書く: 手数は減るが、鍵が、画面の読み取りを通って会話に入る。採らない。
- ユーザー ID を、ページの中身をスクリプトで調べて読む、クリップボードから読む: 画面の作りに頼って壊れやすい。クリップボードには、鍵が入っていることがある。採らない。
- 鍵集めを、別のスキルにする: 入口が 2 つになる。「セットアップして」の 1 つに保ち、手順書を、必要な所で読む形にする。
