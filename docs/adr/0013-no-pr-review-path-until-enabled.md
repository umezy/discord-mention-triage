# ADR-0013: PR レビュー用の先行実装は、有効にする決定まで経路から外す

## 背景と課題

- PR の自動レビューは無効（[ADR-0004](0004-unattended-triage-without-pr-review.md)）。それでも、有効にしたときのための作りが、仕分けの経路に残っていた。
- 開封係は、許可条件を満たした PR の URL を含む件を `kind=pr` と分類し、**自動では `inbox/` に戻さなかった**
  （レビューが 1 時間かかり、二重実行が困る、という前提）。いまはレビューが走らず、その件も、ふつうの仕分けとして動く。
  その仕分けが失敗すると、再試行されず、約 80 分後に「PRレビューが止まっています」と通知されるだけだった。
- 起きる条件は、`pr_policy` に組織と依頼者のロールを設定していて、当てはまる PR の URL を含むメンションが来たとき。
  設定の雛形は、この条件を満たす形になっている。
- 設定の `pr_auto_review` と `pr_review_workdir` は、読むだけで、どこからも使われていなかった。`pr_auto_review: true` と書いても、
  何も起きず、エラーにもならない。

## 決定

- **PR の自動レビューが無効の間は、すべての件を「仕分け」として扱う。** 失敗したら 5 分後に再試行し、3 回で `failed/` へ退避する。
  `kind=pr` の分岐（長いタイムアウト、自動では戻さない、`STALE` の通知）は消す。
- 使われていない設定を消す。`pr_review_workdir` は、古い設定ファイルに残っていても読み飛ばす。
  **`pr_auto_review: true` は、設定の読み込みで拒否する**（`false` は読み飛ばす）。
- `watcher/pr_policy.py` の許可条件は、変えない。件に `pull_requests`（条件を満たした PR）と `pull_requests_blocked`（満たさなかった PR と理由）を
  載せるところまでは残す。ダイジェストの「PRレビュー依頼」の 1 行は、これまでどおり出る。
- レビュー用の別扱いは、自動レビューを有効にする ADR と一緒に戻す。

### 結果

- 得るもの: PR の URL を含む件も、失敗したら自動で再試行される。設定の項目が 2 つ減る。診断の出力から `STALE=` が消える。
- 引き受けるもの: 自動レビューを有効にするときは、種類の分類・タイムアウト・二重実行の防止を、作り直す
  （この変更の前の形は、`pipeline/tick.py` の履歴にある）。
- 変えないもの: 鉄則 3（PR の自動レビューは無効。有効にする実装も、許可条件を緩める変更も、理由を人間に確認してから）。

## 採らなかった案

- `kind=pr` を残し、タイムアウトだけ仕分けと同じにする: 使われない分岐と通知文が残り、次に読む人が「PR は別扱い」と誤解する。
- `pr_auto_review` を残して、`true` のときだけ分岐を生かす: 自動レビューの実装が無いので、`true` にすると「再試行されないだけ」の設定になる。
- `pr_auto_review: true` も読み飛ばす: 有効にしたつもりで運用される。止めて気づかせる。
