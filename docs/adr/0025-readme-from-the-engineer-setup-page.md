# ADR-0025: README は、エンジニア向けのセットアップのページを元に作り、README だけで始められるようにする

## 背景と課題

- [ADR-0016](0016-short-readme-details-in-wiki.md) で、README を「課題とソリューション」と「セットアップ」の 2 章にし、残りを wiki の 8 ページに分けた。
  README からは、どう動くのか、鍵をどう扱うのか、困ったら何をするのかが、wiki を開かないと分からなかった。
- 別に、エンジニア向けのセットアップのページを作っていた。何が変わるか、しくみの図 1 枚、鍵の扱い、4 ステップ（誰が何をするか）、困ったとき（Claude に伝える言葉）を 1 枚にまとめ、細部は折りたたんである。
- umezy さんから、2026-10-10 に「README や wiki は洗練されていない。エンジニア向けのセットアップのページを元に作り直して」と依頼があった。
  公開リポジトリとして出すので、はじめて見る人が、README だけで、何の物か、どう動くか、どう始めるかを判断できる必要もある。

## 決定

- **README は、そのページの構成に合わせる。** 概要、何が変わるか、しくみ（図 1 枚）、必要なもの、鍵の扱い、セットアップ（4 ステップ）、困ったとき、もっと詳しく、ライセンス。
  細部（時間の根拠、よくある `[NG]`、届かないとき、費用、やめ方など）は、`<details>` で折りたたむ。
- **wiki は、README の先を書く 5 ページにする。** しくみ、約束、Discord 側と鍵を用意する、スキルを使わずに進める、困ったとき。
  「どこに何があるか」は「しくみ」に入れる。「プラグインとボットの関係」（この仕組みが使わない物の説明）と、使わなくなった図は、外す。
- スキルと ADR が指している wiki のページ（`get-the-keys.md`、`when-notified.md`、`promises.md`）は、名前を変えない。
- README・wiki と `docs/` の間で、同じことを二重に書かない決まりは、変えない。

### 結果

- 得るもの: README だけで、判断し、始め、困ったときの入口まで分かる。言葉と構成が、エンジニア向けのページとそろう。
- 引き受けるもの: README が長くなる（折りたたみで、画面の上では短く見せる）。「よくある `[NG]`」と「届かないとき」は、README の要点と wiki の細部の 2 か所にあるので、変えるときは両方を直す。

## 採らなかった案

- ADR-0016 のまま、wiki のページだけを直す: README から wiki へ行かないと、しくみも、困ったときの入口も分からない形が残る。
- 折りたたみの中身まで、すべて README に入れる: 自分の手で鍵を用意する手順と、通知の一覧は、スキルが wiki のページを読んで使うので、wiki に置くほうが、直す所が 1 か所で済む。
