# ADR-0016: README は「課題とソリューション」と「セットアップ」だけにし、詳しいことは wiki に書く

## 背景と課題

- README は、仕組みの登場人物、届くまでの時間、設計のポイント、セットアップの各ステップ、届く通知、約束、検証の状態、フォルダの構成までを、
  1 枚に載せていた（192 行、図 6 枚）。umezy さんから「極めて分かりにくい」と指摘があった（2026-10-10）。
- はじめて読む人が知りたいのは、「何がつらくて、どう変わるのか」と「どう始めるのか」の 2 つ。それ以外は、必要になったときに読めばよい。
- セットアップは、`python triage.py ...` の 1 種類のコマンドになったので（[ADR-0015](0015-one-command-one-folder.md)）、短く書ける。

## 決定

- **README に載せるのは、「解決する課題とソリューション」と「セットアップ」の 2 章だけ。** 図は、それぞれ 1 枚。最後に、詳しいページへの表を置く。
- **それより詳しい説明は、`wiki/` に書く。** 1 ページ 1 テーマで、しくみ、セットアップをくわしく、通知が届いたら、約束、いまの状態、
  どこに何があるか、に分ける。絵は `wiki/figs/` に置く。ページの一覧は `wiki/README.md`。
- コマンドの細かい説明と止まったときの調べ方（`docs/setup.md`）、設計（`docs/architecture.md`）、決定の理由（`docs/adr/`）、安全面（`docs/security.md`）は、
  これまでどおり `docs/` に置く。README と wiki からは、リンクするだけにして、同じことを二重に書かない。

### 結果

- 得るもの: README が、1〜2 画面で読める（約 60 行、図 2 枚）。
- 引き受けるもの: 仕組みを変えたときに直す場所が、README・wiki・`docs/` に分かれる。README には、変わりにくいこと（課題、手順の骨組み）だけを書く。
- 守ること: README に章を足さない。足したくなったら、wiki のページにして、README の最後の表に 1 行足す。

## 採らなかった案

- README を短くせず、目次を付ける: 長さは変わらない。最初の 1 画面で、何の仕組みかが伝わらない。
- 詳しい説明を `docs/` に足す: `docs/` は、作業する人向けの細かい文書。絵つきで、エンジニアでない人が読むページは、`wiki/` に分けてある。
- GitHub の Wiki 機能に書く: リポジトリと別の場所になり、変更を PR で見られない。リポジトリの中の `wiki/` フォルダに置く。
