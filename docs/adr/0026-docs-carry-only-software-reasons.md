# ADR-0026: 文書には、ソフトとしての理由だけを書く。リポジトリは 1 つのまま

## 背景と課題

- リポジトリを公開するにあたり、`docs/` と ADR を読み直すと、ソフトの説明のほかに、最初に使った組織での事情（管理者への説明、契約、組織の中での広げ方、前に使っていた仕組みとの比較）が混ざっていた。
  外から読む人には要らず、組織の内情でもある。
- umezy さんから、2026-10-11 に「docs の内容も管理したい」「2 つのリポジトリに分けると、保守が面倒」と話があった。

## 決定

- **リポジトリは 1 つ。** docs と ADR は、コードと同じリポジトリに置き、同じ変更の中で直す。ADR を書く決まり（[ADR-0001](0001-record-decisions-as-adr.md)）も、そのまま続ける。
- **文書には、ソフトとしての事実と理由だけを書く。** 使う組織の事情と、ほかの人の名前は書かない。それは、その組織の文書置き場に置く。決まりは CLAUDE.md に書く。
- 公開の前に、組織の事情だけを扱っていた ADR（0002・0006・0007・0010）は外して、欠番にした。ほかの ADR と docs からも、組織の事情を除いた。
  未決事項は、ソフトとして決めていないことだけにした。

### 結果

- 得るもの: 保守する場所が 1 つ。外から読む人が、ソフトの説明だけを読める。
- 引き受けるもの: 組織での事情（誰に何を説明したか、どの契約で動かすか）は、このリポジトリからは追えない。その組織の文書置き場で持つ。

## 採らなかった案

- 組織の事情を、別の private のリポジトリに置く: 置き場が 2 つになり、どちらに書くかを毎回決め、両方を直すことになる。
- 元のリポジトリを private のまま本体にして、公開用に書き出す（`export-ignore` で組織向けのフォルダを除く）: 書き出しの手間が毎回かかり、公開側に来た変更を、手で写すことになる。
