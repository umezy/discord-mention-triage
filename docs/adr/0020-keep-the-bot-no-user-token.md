# ADR-0020: メンションの取得には、ボットを使い続ける。本人のログイントークンで読む経路は、採らない

## 背景と課題

- 導入でいちばん重い手間は、各自がボットを作り、サーバーの管理者に入れてもらう所（[ADR-0018](0018-per-person-bot-no-shared-host.md)）。
- ボットが無くても、本人のログイントークン（ブラウザの開発者ツールから写せる）で `GET /users/@me/mentions` を引けば、自分宛てのメンションは取れる。
  この経路を採ってよいかを確かめた。
- Discord の文言（2026-10-10 に確認）。
  - [コミュニティガイドライン](https://discord.com/guidelines)の 14 番（2025-09-29 発効）: self-bot・user-bot を使わない。アカウントは、人が使うもので、ボットであってはならない。
  - [公式ヘルプ](https://support.discord.com/hc/articles/115002192352): ふつうのユーザーアカウントを、OAuth2 / bot API の外で自動化することは、禁止。見つかれば、アカウントの停止がありうる。
  - どちらにも、「読むだけ」「自分ひとりで使うだけ」の例外は無い。2024 年の Spy Pet（ふつうの参加者と同じ範囲しか見えないユーザーアカウントで、発言を集めていた）では、
    Discord は、アカウントを停止し、収集と self-bot は規約違反だと述べた（[The Register](https://www.theregister.com/2024/04/16/discord_network_sale/)）。
- 読まれる中身と負荷は、どちらの鍵でも、ほぼ同じ。Discord が線を引いているのは、**誰の名義で、誰の許可で読むか**。
  ボットは、自動処理だと名乗り、管理者が招待し、ロールで見せる範囲を決め、いつでも外せる。本人のトークンでは、管理者も、ほかの参加者も、気づけない。
- ボットのトークンで、数分おきに引くこと（[ADR-0014](0014-poll-search-api-single-entry.md)）は、問題ない。検索の口は、[公式ドキュメント](https://github.com/discord/discord-api-docs/blob/main/developers/resources/message.mdx)にある。
  求められているのは、回数制限を守ること（[公式](https://github.com/discord/discord-api-docs/blob/main/developers/topics/rate-limits.mdx)）で、定期的に引くことを禁じる記載は無い。いまは 2 分おきに検索 4 回、ボットの上限は毎秒 50 回。

## 決定

1. **メンションの取得には、ボットを使い続ける。**
2. **本人のログイントークンで Discord を読む経路は、採らない。** 読むだけでも、自分ひとりで使うだけでも、同じ（鉄則 6 の理由は、この ADR）。
3. **規約の上で白か黒かを分けるのは、鍵の種類。読み方ではない。** Gateway で受けるか、数分おきに引くかは、規約の上では変わらない。
   [ADR-0014](0014-poll-search-api-single-entry.md) の読み方は、変えない。
4. **導入の手間は、ボットを無くす方向ではなく、ボットに頼む権限を小さくする方向で減らす。**
   受付が使うのは、「チャンネルを見る」「メッセージ履歴を読む」と、Message Content Intent。書き込みの権限は、要らない。

### 結果

- 得るもの: 管理者が知っていて、範囲を決められ、止められる形のまま使える。「なぜボットが要るのか」を、文言つきで説明できる。
- 引き受けるもの:
  - 見えるのは、ボットを入れたサーバーの、ロールで見える範囲だけ。DM は、どちらの鍵でも拾えない。
  - 各自がボットを作り、管理者に頼む手間は、残る。
- 分かっていないこと: 読むだけの使い方が、どのくらい見つかり、止められているか（公開された数字は、見つけていない）。
  上は、公開されている文言の読みで、Discord の個別の判断ではない。

## 採らなかった案

- **本人のログイントークン**: 管理者に頼まずに済み、参加している全サーバーが見える。ただし、上のとおり、明文で禁止されている。
  鍵が漏れると、アカウントが丸ごと渡る（全サーバー、DM、本人としての発言）。ほかの人に勧めることも、できない。
- **Discord アプリが PC に置いたデータを読む**: アプリは、受け取ったメッセージを PC に溜めていない（`%AppData%\discord` にあるのは、ブラウザ型のキャッシュと、ログインの情報）。
  安定して拾えない。ログインの情報を読めば、上の案と同じになる。
- **データのエクスポート**: 入っているのは、自分が送ったメッセージだけ（[公式ヘルプ](https://support.discord.com/hc/articles/360004957991)）。届くまでに、日数もかかる。
- **Gateway の常駐に戻す**: 規約のためには、要らない。すぐに届けたくなったときの選択肢として、残る（[ADR-0014](0014-poll-search-api-single-entry.md) の代替案）。
