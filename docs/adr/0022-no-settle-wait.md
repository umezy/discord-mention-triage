# ADR-0022: 投稿から 60 秒待つのを、やめる（検索に出るまでの約 100 秒が、様子見を兼ねる）

## 背景と課題

- 受付は、投稿から 60 秒（`settle_seconds`）経っていないメンションを、何もせずに次の回へ回していた。その間に本人がスタンプか返信をしたら届けない、という
  様子見のため。Discord に常時つないで、メンションをその場で受け取っていた頃に入れた。
- いまは、検索を 2 分おきに引く（[ADR-0014](0014-poll-search-api-single-entry.md)）。投稿が検索に出るまでに、約 100 秒かかる（2026-10-10 の実測で 89・100・117 秒）。
  見つけた時点で、60 秒はもう過ぎている。この待ちは、働いていない。
- スタンプ済み・返信済みの確認は、待ちとは別に、書き出す直前に毎回している。
- umezy さんが、2026-10-10 に決めた。「100 秒かかるので、不要。システムはできる限りシンプルに作り、問題があったときに対処する」。

## 決定

- **投稿から待つ時間を、置かない。** 見つけた回に、スタンプ済み・返信済みを確かめて、書き出す。
- `settle_seconds` の設定、`PENDING=` の出力、「寝かせている件」の数え方を消す。古い設定ファイルに `settle_seconds` が残っていても、読み飛ばす。
- [ADR-0014](0014-poll-search-api-single-entry.md) の決定のうち、「投稿から 60 秒経っていないヒットは、次の回へ回す」を、ここで変える。

### 結果

- 得るもの: 受付の分岐と、設定の項目と、出力の項目が、1 つずつ減る。届くまでの時間は、変わらない（3〜6 分。検索の遅れ、2 分おきの起動、仕分けの時間で決まる）。
- 引き受けるもの: Discord の検索が速くなると、本人がその場で返信する前に、秘書が動いて、要らない下書きを作ることがありうる。
  届くのが早すぎる、要らない下書きが増えた、と分かったら、そのとき対処する。

## 採らなかった案

- 残す（Discord の検索が速くなったときの保険として）: 効いていない仕掛けを、起きていない問題のために持ち続けることになる。問題が起きたら、そのとき足す。
- 秒数を短くする: 設定と分岐が残る。効かないことは、変わらない。
