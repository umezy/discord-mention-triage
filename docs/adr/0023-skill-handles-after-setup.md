# ADR-0023: 動き出したあとの相談（状態を見る・調べる・外す）も、セットアップのスキルが受ける

## 背景と課題

- セットアップは、スキルが進める（[ADR-0017](0017-setup-as-a-skill.md)）。一方、動き出したあとの「動いているか」「なぜ届かないか」は、
  人が `python triage.py status` と `python triage.py check` を打って、出力を読む前提で説明していた。
- umezy さんから、2026-10-10 に、「（`status`、次に `check`、の流れも）スキルでラップしたい」と依頼があった。
  読む人が気にしなくてよいコマンドは、説明から外したい、という方針の続き。

## 決定

- **動き出したあとの相談も、同じスキル（`triage-setup`）が受ける。** 「状態を見て」「届かなくなった」「通知が来た」「外したい」と言われたら、
  Claude が `status`、`check`、必要なら `run --dry-run` を自分で実行し、出力を読んで、原因と、相手がすることを 1 つ伝える。
- **スキルを分けない。** 入口は「このフォルダで、Claude Code に頼む」の 1 つに保つ。スキルの説明（いつ使うか）に、相談の言い方を足す。
- **新しいコマンドは足さない。** 実行するのは、これまでと同じ `python triage.py ...`（[ADR-0015](0015-one-command-one-folder.md)）。
- 外す（`uninstall`）は、PC に残る変更なので、確かめてから実行する。鍵を無効にする操作（Webhook の削除、トークンのリセット）は、相手がする。

### 結果

- 得るもの: 人向けの説明から、`status`・`check` を打つ手順を外せる。「Claude Code に、起きたことを伝える」で済む。
- 引き受けるもの: スキルの名前（`triage-setup`）と、中身（セットアップと、そのあとの相談）が、少しずれる。
- まだ確かめていないこと: 実際に「届かなくなった」と頼んで、スキルがこの順に調べること。

## 採らなかった案

- 相談用のスキルを、別に作る: 名前は分かりやすいが、入口と、直す場所が 2 つになる。
- 診断をまとめて実行する新しいコマンドを足す: `status` と `check` で足りている。読んで伝える部分が要るので、スキルに任せる。
